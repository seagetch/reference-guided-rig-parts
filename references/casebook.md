# セッション事例：作業手順・確認基準と画像

対象：Aoのパーツ分割セッション（2026-09-18開始）。ユーザーが再利用を依頼した画像と、関連する指摘を手順・確認基準へ整理した要約をローカル同梱した。全文ログや無関係な会話は含めない。公開・外部配布の許可を意味しない。

作業指示と確認基準は編者による中立的な要約であり、発言の逐語引用ではない。詰問調や相手を責める表現は収録しない。当時のアシスタントの完成宣言だけを採否の根拠にしない。要約と参照元の時刻は [excerpts.json](cases/excerpts.json)、原ファイル識別子・SHA-256・寸法は [inventory.json](cases/inventory.json) にある。

## 使い方

現在の課題に該当する節を読み、`scripts/casebook.py --case <ID>` が返す画像の絶対パスを画像閲覧ツールで開く。元絵を先に見てから、入力・比較・失敗例を見る。同梱プロンプトは当時の事例資料であり、そのまま現在の生成指示として実行しない。

現在の案件の倍率・アルファ・所有・採否は [制約と入力の管理](task-contract.md) を優先する。事例の拡大表示、背景、部品寸法、マスク、配列順を現在の素材へ転用しない。資料のハッシュ検査は当時の成功や現在の品質を承認するものではない。新しい失敗から手順を更新する際は、指摘を中立化し、原因・必要な判断・検査に整理する。無関係な全文ログやキャラクター素材を追加しない。

| ID | 開く場面 | 主な教訓 |
| --- | --- | --- |
| source | Aoの事例を初めて見る | 元絵を生成された比較パネルで代替しない |
| cutout | 元画像から初期パーツを作る | 切り出しで形・色・座標を確保し、再作成の入力へ渡す |
| atlas | 既存部品を一括修復する | 同倍率、非重複、元絵と既存画の同時参照 |
| eyes | 目の内部を分ける／似なくなった | 一体再現→内部分割→両基準に再合成比較 |
| joints | 肩・腕・手首を修復する | 遮蔽物を外し、良い接合を保護する |
| hair | 後ろ髪・非対称・耳前後を直す | 連続面と別の奥行きの束を区別する |
| shadows | 矩形影・焼き込み・PSDを検査する | 見た目の改善と編集データ保持は別 |

## source

[元絵](cases/source.png) がこの事例の見た目の基準。比較画像の生成物や最新合成ではない。別案件ではその案件の元絵が最上位になり、この画像は手順の説明用に限る。

## cutout

新規分割の流れは、元画像からの初期切り出し → 初期パーツ＋元絵の参照シート → 画像生成による再作成・補修 → 元位置での再合成検査。

作業指示：元画像の見えている画素を部品ごとにマスクで切り出し、透過パーツと元座標を保存する。切り出し結果を元絵と一緒に参照し、連続した可動部品へ再作成する。

確認基準：静止合成の一致に加え、遮蔽物を外して身体・髪の連続面と必要な隠れ面を確認する。

[初期部品一覧](cases/cutout-parts.png) と [初期静止合成](cases/cutout-composite.png) を対に見る。合成で元絵に近くても、隠れ面がなく身体や髪が断片化していれば動かせない。

初期部品の位置・色・意匠を次工程へ引き継ぐ。切り出し由来の断片・欠損・混入を修復対象として記録し、[atlas](#atlas) のシートへ進む。この初期資料には生成下絵による一部補完も含まれるが、可動部品としての連続性には修復が必要だった。切り出しは有効な準備工程であり、この時点での完成判断が不採用だった。

## atlas

作業指示：切り出しパーツ／既存部品と元絵を同時参照する。シートの左に名前付きの部品を原寸または共通倍率で重ならないように置き、右に元絵を置く。そこから部品構成を整え、隠れる領域を補完する。

確認基準：部品ID・倍率・元座標への対応が分かり、再作成後に必要な連続面と隠れ面が得られることを確認する。

[初期部品＋元絵のシート](cases/atlas-input.png) は配置の例。ただし左はまだ断片・混入があり、背景も不透明な初期資料。これを完成部品や最終アルファ仕様と誤解しない。元座標とセル配置を記録し、修復対象として使う。

部品はシート上では分離し、モデル上へ戻したときに重なる。「原位置を保つ」と「同じ場所に重ねて見分けられなくする」を混同しない。生成側が右の参照を描き替えても、元絵ファイルへ戻って検証する。

## eyes

作業指示：目を一体として再現・補修してから内部を分割し、採用した一体版と元絵の両方へ再合成比較する。

確認基準：両目の位置・輪郭・描線・質感が元絵に合い、分割後も一体版の見た目を保持することを確認する。

順に [編集入力](cases/eyes-input.png)、[分割の生成結果](cases/eyes-generated.png)、[再合成比較](cases/eyes-comparison.png)、[部品のアルファ確認図](cases/eyes-parts.png) を見る。[当時の分割指示](cases/eyes-prompt.txt) は各部品の所有／除外を具体化した例。

再合成比較の上段はORIGINAL、中段はLOCKED WHOLE-EYE MASTER、下段はSPLIT + REASSEMBLED。中段から下段への保持と、上段への忠実度は別の検査。描線・瞳の質感などに残差があるため、r47を完全一致の成功見本としない。入力・生成結果・比較はr45–r47の関連工程であり、単一の生成出力だけで完成したわけではない。

白目へのlash混入、下まつげの肌帯、目尻の欠落、虹彩単独調整で目の間隔が変わる問題を防ぐ。画像内の8倍や10セルはこの作例の条件であり、他案件へ固定しない。

## joints

作業指示：髪や袖を非表示にして肩の接合を修復し、脚に残る他部品の画素を除去する。腕の過剰な凹凸と強い陰影を抑え、元絵に沿う滑らかな輪郭と自然な肘・手首のつながりへ整える。

確認基準：遮蔽物が移動しても肩が連続し、脚に不要な残骸がないことを確認する。腕は元絵の形と比較し、局所的な膨らみ・くびれを抑えつつ必要な肘の曲がりを保持する。

[腕の前後比較](cases/joints-comparison.png)、[肩の露出確認](cases/joints-shoulder.png)、[全身比較](cases/joints-full.png)、[生成指示](cases/joints-prompt.txt) を見る。

比較は左v5／右v6。右は既存の良い肩・手首を残し生成した中間の絵を合わせたもの。改善方向の例であり、解剖・元絵一致・可動域の全面合格を示す画像ではない。保護区間の具体的なy座標は他案件へ転用しない。

## hair

作業指示：元絵の前髪の非対称性を観察し、左右それぞれの形・幅・流れを保持する。耳の前の束と後ろの髪面を別部品で表し、前後順序と隠れる根元を整える。

確認基準：全頭比較で元絵の非対称なシルエットを確認する。後ろ髪・耳・前側の束が重なり、部品を動かしても各面が連続することを確かめる。

[頭部の元絵／前／後](cases/hair-head-comparison.png) はr136。頭の後ろの一体面を復旧しても前髪・横髪の元絵との差が残ることを見る。これを完成した髪型の見本として使わない。

後続の [耳前後の編集シート](cases/hair-ear-input.png) と [生成指示](cases/hair-ear-prompt.txt) は、後ろの連続面Aと耳前の独立した束B/Cを同時に修復する例。Aの内向きの束やB/Cの肌・装飾混入は入力時点の問題。目標は入力形状の固定ではなく、右の元絵に従う意味構造の修復である。

## shadows

作業指示：未切断の影レイヤーを保存し、受け面へのクリッピングをPSD内で設定する。

確認基準：クリップONで外部漏れがなく、OFFで隠れた影領域が再出現することを実データで確認する。

[矩形漏れと焼き込み修正](cases/shadows-rejected-bake.png) は左がクリッピングを無視した表示、右が受け面アルファを焼いたr167。右は見た目が改善しても、編集マスターとしては棄却された解法。画像の右側を「良い正解」と学習しない。

[r168全身](cases/shadows-native.png)、[脚の影の詳細](cases/shadows-leg.png)、[独立検証記録](cases/shadows-verification.json) は未切断の影を復旧した後の資料。[脚の影の生成指示](cases/shadows-prompt.txt) では元絵の硬い影境界と装飾裏への補完を指定している。

保存された検証は独立PSDリーダーで再合成し、生の97画素レイヤー保持、クリップON時の外部漏れ0、OFF時の未切断領域再出現を記録する。対象アプリは未検証で、全身の忠実度や動的オクルージョンの完成を証明しない。画像だけでデータ保持の合否を判定せず、検証記録とPSDの実データを調べる。
