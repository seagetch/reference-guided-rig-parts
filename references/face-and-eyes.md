# 顔：一体再現から内部へ

まず [eyes事例](casebook.md#eyes) の元絵・一体の目・分割再合成を実際に見る。改善途中の例であり、同梱の目の形を他のキャラクターへ転用しない。

## 二段階の検証

1. 元絵を参照して一体の目を再現・補修し、顔上で両目の位置・形・質感を合わせる。既に良い一体資産があるなら無意味に再生成しない。
2. 採用した一体の目と元絵の両方を参照し、同倍率の関連部品アトラスで内部を分割する。
3. 分割再合成が一体の目を保持しているか、さらに元絵に合っているかを別々に判定する。一体版が元絵と違えば「一体版と同じ」だけで合格にしない。

## 所有する絵

| 部品の例 | 含めるもの | 含めないもの |
| --- | --- | --- |
| 顔の下地 | 髪・眉・目・鼻・口の下へ続く肌、元絵の必要な頬の色 | 首、襟、独立特徴の残像、首に属する影 |
| 白目 | 虹彩の下まで続く面、元絵に必要な陰影 | lash、赤い目尻、肌帯、追加の囲み線 |
| 虹彩 | 瞳孔・ハイライト、まぶた裏の補完 | 白目、lash、肌 |
| 上まつげ・まぶた線 | 元絵の線、太さ、先端 | 虹彩・白目の塗り |
| 二重の折れ線 | 元絵に存在する淡い折れ線、髪裏の連続部分 | まつげへの吸収、元絵にない追加線 |
| 下まつげ | 元絵に存在する点・短線 | 新しい太い弧、帯状の肌 |
| 目尻 | 元絵にある独立した目尻の形 | 不要な内眼角や別のlash |
| 眉 | 元絵の細い線、自然な濃淡、髪の裏へ続く眉 | 肌や影の帯、前髪、矩形の背板 |
| 鼻 | 元絵の立体的な塗り、必要な影・光点・鼻孔 | 光点だけへの単純化、不要な肌矩形 |
| 口 | 口角、開き、唇、歯・反射など元絵にある要素 | 抽出範囲による唇の欠落、周囲の肌の背板 |

枚数はこの絵の例。可動要件でハイライトやまぶた線を独立させるなど調整する。白目の影と混入した黒いlashを混同しない。動きに応じて変わる影は独立した影として設計する。虹彩は必要な全形を残して白目等とのクリッピングで表示を制御する。

顔と首は独立した可動部品として検査する。顔の下地は輪郭・頬を保ち、髪や特徴を隠したときに穴、鼻の光点、首側の影が残らないか確認する。顔や首が影を所有する範囲と、別部品が落とす影は分ける。首の接合・幅は [身体・衣装・髪](body-clothing-hair.md) を参照する。

楕円・ポリゴンは初期選択の補助であり、元絵の輪郭の代わりではない。「白目と虹彩を引いた残り」を全てまぶたに渡さない。残差には肌・影・別部品が含まれる。各部品の所有を単体で確認する。

虹彩の補完マスクは実際に遮蔽された領域へ限定する。「推定楕円から可視虹彩を除いた全域」を隠れ面として足すと、見えている目頭の白目を覆う。可視虹彩のRGB一致だけでなく、白目の内外角・幅・陰影が保存され、補完が隣の可視部品へ侵入しないことを確認する。白目は虹彩の下まで続く面とし、虹彩を隠す／必要な範囲で左右へ動かす検査を行う。

眉・鼻・口の有無、位置、角度、描線を独立確認する。眉を髪の一部に吸収したり、顔を動かすために全部を平面画像に戻したりしない。

眉は左右別に、眉頭・曲線・角度・幅・濃度・先端を原寸で照合する。位置の並進だけで曲線まで合ったと判断しない。肌色残骸を隠すための一律のRGB暗化やアルファ増幅は、眉を太く濃くするので除去処理として使わない。元画素を矩形ごと戻して影の帯を付け直さない。

鼻・口は肌と連続した柔らかな描画を持ち得る。色閾値・局所明暗差・狭い走査範囲だけで境界を決めず、元絵の立体感・口角・反射まで確認する。不要な肌の背板を除くことと、特徴に必要な塗りを削ることを区別する。特徴を非表示／移動したときは下地側の残像も調べる。

前髪の修正は、眉混入だけでなく毛束間の半透明なごみと置換境界を見る。二つの矩形を貼って継ぎ目を残さない。二重線とまつげ先端は別に所在を確認し、淡い折れ線を消して一重にしない。元絵で先端が横髪の前へ出ていれば、その前後関係を保持する。必要なら独立して動く先端を分け、髪に穴を焼き込んで取り繕わない。

## 判定

元解像度の両目間隔、目頭・目尻、上下まぶた、虹彩の中心と径、白目の見え方、ハイライト、眉角度を確認する。案件で許可された検査表示で、局所比較と顔全体の印象を併用する。元絵の非対称性を保つ。

少数の輪郭サンプルの0–1px誤差、RGB損失の減少、瞳だけの良さを顔全体の合格としない。ユーザーの指定が数px以内なら、元絵解像度で測る。分割により目尻が消えたりlashが強くなれば、一体再現の採用版に戻して所有を修復する。

各眼の局所、両眼を含む顔全体、髪を外した状態、部品単体を同じ版で比較する。巻き戻しは退行防止であり、最初の未解決事項が残るなら [合否と反復](acceptance.md) に従って修復を続ける。
