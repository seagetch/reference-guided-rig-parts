# 影、前後関係、編集可能なPSD

[shadows事例](casebook.md#shadows) を見る。矩形漏れの焼き込み修正は見た目が改善しても、編集要件に反して棄却された例である。

## 影のデータ

表面自体の陰影と別部品が落とす影を分ける。髪→顔、スカート→太腿／後ろの布など、影ごとに投影元、受け面、手前の遮蔽物、ブレンド・濃度を記録する。元絵の硬い境界を汎用のぼかしへ置換しない。

装飾で隠れる部分や遮蔽物の裏へ必要な影を補完する。編集マスターでは現在の受け面アルファを影PNGへ焼き込まない。未切断の影フィールドをMultiplyレイヤーとして保持し、PSD内で受け面へのネイティブクリッピングを設定する。これは自然な部品輪郭の透過を禁止することではない。

矩形漏れがあれば、クリッピング属性、受け面、グループ、順序、リーダー対応を診断する。非対応アプリのための焼き込み版が必要なら、ユーザーの目的に沿って別の互換出力を作り、マスターを保持する。一般的なPSD整形スキルのマスク適用を無条件に実行しない。

## 保存と検査

順序・クリッピング属性だけの誤りなら、必要な構造だけを修正し、無関係な画素を再生成しない。次の三つを別に検査する。

| 検査 | 問い |
| --- | --- |
| PSD全体の順序方向 | 台帳どおりの前後で保存・再合成されるか。全体が反転していないか |
| 各部品ペアの前後 | 全体方向が正しくても、胸衣／コルセット等の特定の関係が元絵と逆ではないか |
| クリッピングの接続 | 影や虹彩が意図した受け面に属し、順序変更で別レイヤーへ接続していないか |

### 順序の対応を校正する

部品台帳の方向、PSDのレコード順、読み書きライブラリの子配列、合成時の走査方向、レイヤーパネルの表示順を区別する。「PSDだから上から下」等の推測で `.reverse()` を追加しない。使うライター・リーダーの対応を実データで確認し、対応表を記録する。別ライブラリへ同じ方向を無条件に移植しない。

新しい保存経路、または「PSD全体の順序が逆」という指摘には、次の小さな校正を使う。

1. 後ろの不透明面と、それに部分的に重なる手前の不透明面を作り、手前の色が出る重なり位置を**書き出し配列とは独立に**期待値として決める。必要なら受け面より広い影を含むクリッピング例も作る。
2. 実際に使うライターで保存する。完成プレビューの一致を検査結果にしない。
3. 別のPSDリーダーの合成機能で、埋め込みプレビューを使わずに再合成する。配列を期待画像に合わせて再反転してから自作合成する方法だけでは独立検証にならない。
4. 重なり位置、前後、クリッピング先を期待値と照合する。生画素や位置が同じでも順序が違えば不合格。校正と実ファイルの読込結果を別に保存する。

書き出し側の反転を検証側でも反転すると、同じ誤りを打ち消して「合格」になる。独立したライブラリ名が記録されていても、この検証は無効である。元絵から確認した前後関係と、独立した合成結果の両方が必要。

### 実ファイルの確認

1. 元絵から前後ペアを決める。例は後ろ髪→顔、首→顔、脚→前スカート、袖口→袖等だが、その案件の実際の構造を優先する。説明に「Aの下へ続ける」と書いたBが、実装でAの手前に置かれていないか照合する。
2. レイヤーID、位置、RGBAハッシュ、可視性、濃度、ブレンド、クリッピング先、グループとその順序を記録する。変更対象外の生画素・配置・属性を前版と照合する。順序だけの修正なら画素を変更しない。
3. 保存完了後のPSDを独立リーダーで再合成し、全身と局所を確認する。検証は読み取り専用とし、PNG・台帳・PSDのハッシュへ結び付ける。
4. 全体の順序方向、各前後ペア、全クリッピング先を個別に照合する。ライターと同じ誤った台帳から期待するペアまで自動生成しない。
5. 影クリップONで受け面外へ漏れず、OFFで必要な隠れ領域が復元することを確認する。影を切断済みならこの検査を満たさない。ネイティブクリッピングを無視する表示の問題と、PSD保存順の問題も分ける。
6. 対象アプリで読込を確認する。未検証ならその範囲を明示し、独立リーダーの成功から推定しない。合成エンジン間の差は範囲と原因を記録し、生レイヤー一致と表示完全一致を混同しない。

最初の順序訂正後に再度「逆」と指摘されたら、初回不具合に加えて訂正後検証の失敗として記録する。同じ検査を再実行するだけで修正済みとせず、配列の対応・期待値の独立性・実際に開いたPSDの版を再確認する。全体反転を直しても、個別ペアの逆転まで直ったとはしない。

事例にある画素数やレイヤー数は、そのファイルの保存済み検証結果であり、新案件の期待値ではない。

## 動的な遮蔽への引き渡し

静止PSDの影とクリッピングだけで投影影が自動追従するとは言わない。顔や髪を動かしたときの投影元・受け面・手前遮蔽物の関係、隠れ面のデータを台帳として渡す。実際の変形・投影・マスク追従はリグ工程で検証する。資産の簡易移動試験と実機リグの全可動域保証を区別する。
